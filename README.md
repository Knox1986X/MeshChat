# MeshChat — Анонимный мультитранспортный E2E-мессенджер (Web + Android APK + Server)

Production-ready MVP анонимного мессенджера со сквозным шифрованием **по умолчанию для всех личных чатов и файлов** (Signal X3DH + Double Ratchet + Sealed Sender на канонической кривой WebCrypto P-256), Zero-Knowledge аутентификацией (Argon2id 64 МиБ / scrypt $N=2^{17}$), сменными транспортами (`WSS`, `Tor .onion v3`, `I2P .b32.i2p`, `WebRTC P2P Mesh`, `FallbackTransport`) и нулевым хранением IP-адресов и открытых текстов на сервере.

- **Готовый Android-пакет (`MeshChat.apk`):** `381 КБ` (подписан по схеме APK Signature v2 + v3, `minSdk 26` / Android 8.0+, включает встроенный офлайн/Wi-Fi Mesh-узел и нативный SOCKS5-мост к Orbot Tor).
- **Вес веб-клиента (включая Preact, Argon2id WASM, криптоядро и 5 транспортов):** `342 КБ` raw / `97 КБ` Brotli (`< 0.9 с` холодный старт на 3G, `< 80 мс` тёплый старт из Service Worker).
- **Внешние npm-зависимости на сервере:** `0` (чистый Node.js 20+).

## Установка и режимы работы `MeshChat.apk` на Android

Готовый установочный файл находится в корне проекта: **`/home/user/messenger/MeshChat.apk`** (пересборка из исходников одной командой: `npm run build:apk`).

После установки `MeshChat.apk` на телефон доступны три сценария работы:
1. **Автономный / Локальный Wi-Fi Mesh без интернета (0 серверов):**
   - На экране входа или в «Настройках» включите переключатель **«📡 Раздавать Wi-Fi Mesh узел на телефоне (:3000)»**.
   - Соседние телефоны в той же сети Wi-Fi или мобильной точке доступа указывают показанный адрес (например, `http://192.168.43.1:3000`) в поле «Адрес сервера MeshChat» и общаются напрямую со сквозным шифрованием Signal X3DH + Double Ratchet даже при полном отсутствии интернета.
2. **Подключение к своему облачному или домашнему узлу:**
   - Введите адрес вашего развёрнутого сервера (`https://<имя>.onrender.com`, `https://<имя>.fly.dev` или домашний адрес) на экране входа / в настройках.
3. **Работа через Tor (`.onion`) на Android:**
   - Запустите бесплатное приложение **Orbot** на телефоне (`SOCKS5 127.0.0.1:9050`) и укажите `.onion`-адрес вашего узла — встроенный в APK модуль `MeshSocksBridge` (`127.0.0.1:17700`) автоматически направит и HTTP API, и WebSocket в Tor с удалённым резолвингом `ATYP=0x03` без утечки DNS, а окно приложения защищено от перехвата скриншотов флагом `FLAG_SECURE`.

## Быстрый старт на `localhost` (2 минуты)

Требуется только **Node.js >= 20.0.0** (без сборки, без СУБД, без `npm install` в продакшене):

```bash
cd messenger
npm test        # Прогон 12 криптографических, транспортных и серверных автотестов (~4.5 с)
npm start       # Запуск слепого сервера на http://0.0.0.0:3000
```

Откройте две вкладки (обычную и приватное окно):
1. Зарегистрируйте `@alice` и `@bob` (без телефона и почты; при желании сохраните 256-битный `Recovery Kit`).
2. Добавьте собеседника по `@username`, сверьте **8 эмодзи / 60 цифр кода безопасности**, отправьте сообщение и одноразовый зашифрованный файл (`🔥 1x`).
3. Проверьте «Голую правду»: откройте `http://localhost:3000/q/alice` в гостевом окне без входа и отправьте E2E-вопрос.
4. Нажмите `Esc` дважды (`Esc Esc`) — мгновенно включится экран прикрытия («Финансовый отчёт Q4.xlsx»).

## Бесплатное развёртывание в интернете за < 15 минут (0 ₽, без платных подписок)

### Вариант А: Облако Render Free + Cloudflare R2 Free (10 минут, 0 ₽)

**Компромисс бесплатного тарифа:** на Render Free контейнер «засыпает» после 15 минут простоя (холодный старт при следующем визите ~25–40 с), а локальный диск контейнера эфемерный. Чтобы не терять зашифрованные ящики и блобы при перезапуске контейнера, сервер оснащён встроенным зеркалом **AWS SigV4 (`server/s3-mirror.mjs`)** — он автоматически сохраняет сжатые зашифрованные снапшоты в бесплатный бакет **Cloudflare R2 (10 ГБ бесплатно)** или **Backblaze B2 (10 ГБ бесплатно, без привязки карты)**.

1. **Создайте бесплатный S3-бакет (3 мин):**
   - В Backblaze B2 (не требует банковской карты на первые 10 ГБ) или Cloudflare R2 создайте приватный бакет `veil-blind-store` и выпустите ключ чтения/записи (`S3_ENDPOINT`, `S3_KEY_ID`, `S3_SECRET`).
2. **Опубликуйте репозиторий на GitHub / GitLab (2 мин).**
3. **Запустите Blueprint на Render.com (5 мин):**
   - В панели Render нажмите **New + -> Blueprint** и выберите репозиторий (файл `render.yaml` подхватится автоматически).
   - Вставьте 4 переменные бакета (`S3_ENDPOINT`, `S3_BUCKET`, `S3_KEY_ID`, `S3_SECRET`) и нажмите **Apply**.
   - Через ~90 секунд мессенджер будет доступен по `https://<ваше-имя>.onrender.com` с автоматическим TLS и `WSS`.

### Вариант Б: Домашний сервер / Raspberry Pi + Tor `.onion` + I2P `.b32.i2p` (12 минут, 0 ₽)

Идеальный вариант по приватности: сервер физически стоит у вас дома, не засыпает, а доступ к нему открывается одновременно как скрытый сервис **Tor Onion v3**, скрытый узел **I2P** и (по желанию) через бесплатный HTTPS-туннель без белого IP.

1. **Скопируйте папку `messenger` на Raspberry Pi / мини-ПК (Debian/Ubuntu) и запустите установщик (5 мин):**
   ```bash
   chmod +x install.sh
   ./install.sh
   ```
   Скрипт создаст `.env` со случайными 256-битными ключами (`0600`), соберёт изолированные read-only контейнеры `veil`, `tor` и `i2pd`, дождётся генерации адреса **`.onion` v3** и автоматически пропишет его в конфигурацию узла.

2. **Узнайте сгенерированные скрытые адреса Tor и I2P (1 мин):**
   ```bash
   # Адрес Tor Onion v3 (56 символов):
   docker exec veil-tor cat /var/lib/tor/veil_hs/hostname

   # Адрес I2P (.b32.i2p):
   docker logs veil-i2pd 2>&1 | grep -i ".b32.i2p"
   ```
   *(Если вы хотите работать **исключительно** внутри Tor/I2P без открытого порта в локальной сети, укажите `LISTEN_BIND=127.0.0.1` в `.env` и выполните `docker compose up -d`.)*

3. **Опционально — бесплатный внешний HTTPS/WSS без белого IP и покупки домена (4 мин):**
   - **Способ 1 (за NAT провайдера — Cloudflare Tunnel, 0 ₽):**
     ```bash
     cloudflared tunnel --url http://127.0.0.1:3000
     ```
     Выдаёт готовый публичный `https://*.trycloudflare.com` с поддержкой `wss://`. *(Компромисс: Cloudflare терминирует внешний TLS и видит IP клиента, но НЕ может расшифровать Signal E2E-пакеты внутри WebSocket).*
   - **Способ 2 (есть белый IP, но нет платного домена — Let's Encrypt + `sslip.io`, 0 ₽):**
     Используйте Caddy с бесплатным DNS-отражателем `<ваш-IP-через-дефис>.sslip.io` — Caddy автоматически выпустит валидный сертификат Let's Encrypt без регистрации домена:
     ```bash
     caddy reverse-proxy --from 203-0-113-42.sslip.io --to 127.0.0.1:3000
     ```

## Как подключаться через Tor и I2P со стороны клиента

Стандартная песочница обычных браузеров (Chrome/Safari/Firefox без системного прокси) технически не умеет резолвить `.onion` и `.i2p` напрямую. В Veil поддерживаются оба честных бесплатных сценария без сторонних публичных шлюзов (`tor2web` намеренно не используется, так как компрометирует анонимность):

1. **Нативно (рекомендуется для максимальной анонимности):**
   Откройте `.onion`-адрес сервера прямо в **Tor Browser** (Desktop/Android) или через **Orbot**. Переключите в «Настройки -> Транспорт» режим **`Только Tor (.onion)`** — клиент подключится напрямую без промежуточных утилит и жёстко заблокирует WebRTC/клирнет (Fail-Closed).
2. **Из обычного десктопного браузера через локальный SOCKS5-мост:**
   Убедитесь, что на компьютере запущен демон `tor` (`127.0.0.1:9050`), Tor Browser (`127.0.0.1:9150`) или `i2pd` (`127.0.0.1:4447`), и запустите на своей машине локальный мост:
   ```bash
   npm run bridge
   # Слушает строго 127.0.0.1:17700 и проксирует WS в SOCKS5 с удалённым DNS (ATYP=0x03)
   ```
   После этого выберите в настройках мессенджера режим **`Только Tor (.onion)`** или **`Только I2P (.b32.i2p)`** и укажите скрытый адрес узла.

## Переменные окружения сервера (`server/index.mjs`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` / `PORT` | `0.0.0.0` / `3000` | Адрес и порт HTTP/WebSocket сервера |
| `DATA_DIR` | `./data` | Каталог WAL-журнала, снапшотов и зашифрованных блобов |
| `STRICT_FRAME` | `0` (`1` в Docker) | При `1` включает `frame-ancestors 'none'` в CSP против clickjacking |
| `INVITE_ONLY` | `0` | При `1` регистрация доступна только по одноразовым инвайт-кодам |
| `POW_BITS` | `14` | Базовая сложность Hashcash Proof-of-Work (адаптивно растёт до 20 бит при спаме) |
| `MAX_BLOB_MB` | `50` | Лимит размера одного зашифрованного вложения (МБ) |
| `ONION_ADDRESS` | *(из файла Tor)* | Публикуемый в `/api/health` `.onion`-адрес скрытого зеркала |
| `I2P_ADDRESS` | *(пусто)* | Публикуемый в `/api/health` `.b32.i2p`-адрес зеркала I2P |
| `TURN_HOST` / `TURN_SECRET` | *(пусто)* | Хост и HMAC-секрет coturn для эфемерных 5-минутных паролей звонков |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_KEY_ID`, `S3_SECRET` | *(пусто)* | Реквизиты бесплатного S3-бакета (R2/B2) для облачного зеркалирования |
| `METRICS_TOKEN` | *(пусто)* | Bearer-токен доступа к обезличенным метрикам `/api/metrics` |
