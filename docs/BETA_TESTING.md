# Тестирование диагностической Android-сборки

Это подготовка к бете, **не бета готового мессенджера**. Переписка, E2EE и сеть
ещё не реализованы. Не вводите реальные данные/ключи и не используйте LAB для связи.

## Что присылать

1. Установите APK из artifact именно указанного CI run, не старый hardware-only APK.
   Debug signing key runner может меняться: при конфликте подписи удалите старый
   LAB (его тестовые данные потеряются). Не отключайте проверку подписи ОС.
2. Настройте сильную биометрию Android; LAB требует Android10/API29 или новее.
3. Нажмите «Очистить журнал», затем запустите **один** сценарий ниже.
4. Дождитесь завершения/ошибки и очистки (кнопка просмотра даёт снимок текущих событий).
5. «Просмотреть и экспортировать отчёт» → проверьте текст → «Сохранить .txt…».
   Выберите место хранения сами. Облачный DocumentsProvider может загрузить файл;
   для локального хранения выберите локальную папку. Открытие выбора файла отменяет
   активный тест. CLEANUP_OK может появиться позже — при необходимости экспортируйте
   ещё раз после завершения очистки.
6. Пришлите сюда полученный `MeshChat-diagnostics.txt` и отдельно напишите сценарий,
   модель телефона (если согласны её раскрыть), ожидаемый и фактический результат.
   Не присылайте полный logcat/Android bugreport, ключи, содержимое БД, приватные
   пути, серийный номер, биометрические данные или записи экрана с личными данными.

## Сценарии (по одному отчёту на сценарий)

- StrongBox: два подтверждения биометрии; ожидаются WRAP_OK, UNWRAP_OK,
  NATIVE_PROBE_OK, CLEANUP_OK. Это проверка пустой временной БД, не E2EE.
- Телефон без StrongBox: явный отказ, без автоматического перехода на TEE.
  Если хотите отдельно проверить TEE, используйте отдельную кнопку/consent.
- Отказ/отмена в первом и втором BiometricPrompt: не должно быть успешного
  завершения native probe; ожидается очистка временных данных.
- Уход в фон или блокировка экрана посреди теста: CANCELLED, отзыв доступа,
  отсутствие позднего успешного UI-результата, затем CLEANUP_OK.
- Кнопка остановки и повторный запуск; дождитесь очистки. Ошибка CLEANUP_FAILED
  означает неуспешную очистку; не объявляйте тест пройденным.
- Просмотр, отмена сохранения, сохранение, очистка журнала. Экспортированный ранее
  файл удаляется отдельно: очистка внутри LAB его не отзывает.

## Границы диагностики

- Только enum allowlist событий; API журнала не принимает строки, exceptions,
  ByteArray, ключи, сообщения или native/provider error text.
- До256 последних событий, FIFO; `dropped` показывает число вытесненных событий.
- RAM-only, нет фонового сбора/отправки/analytics/INTERNET permission. После process
  death/пересоздания Activity журнал теряется; Java/native crash logs и ANR пока
  не собираются. Это ограничение, а не доказательство отсутствия crash.
- Отчёт содержит source revision, versionName, Android API и последовательность
  кодов, без wall-clock, IP, alias, UUID, модели/серийного номера/идентификаторов.
  Сам факт аппаратного тестирования и Android API тоже могут быть чувствительными:
  просмотрите файл и отправляйте только по собственному решению.
- Экспорт использует системный CreateDocument с явным выбором, без exported
  FileProvider/IPC и без разрешений общего доступа к памяти. Файл после экспорта
  вне контроля приложения и не защищается его FLAG_SECURE/backup exclusions.
- Тесты эмулятора не доказывают StrongBox/TEE/BiometricPrompt/OEM поведение.

APK и CI evidence: [PROGRESS.md](PROGRESS.md). Отчёты тестировщика не коммитить
в репозиторий: даже редактированный лог может содержать сведения об окружении.
