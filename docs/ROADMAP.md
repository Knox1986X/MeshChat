# Roadmap

Отмечено, что уже есть, и что логично делать дальше — в порядке пользы.

## Сделано (v0.1)

- [x] Ed25519-личность, приглашения, safety number, Argon2id-бэкап
- [x] X3DH + Double Ratchet, XChaCha20-Poly1305, паддинг до 256 байт
- [x] relay: HTTP + WebSocket + long-poll, PoW, TTL, journal, статика UI
- [x] транспорт «git-репозиторий» (GitHub Contents API)
- [x] локальная шина (BroadcastChannel)
- [x] очередь исходящих, ретраи, дедуп, fanout по транспортам
- [x] PWA: manifest, service worker, offline shell, RU/EN
- [x] исчезающие сообщения, отчёты о доставке/прочтении, «печатает»
- [x] файлы до 8 МБ чанками
- [x] 29 тестов: крипто, ratchet, e2e через реальный relay, перезапуск, UI, boot приложения, отдельный процесс relay
- [x] Docker, compose, fly.toml, systemd-инструкции, Tor

## Следующее (v0.2)

- [ ] **Sealed sender**: передавать `ik`/`ek` инициатора в зашифрованном виде,
      чтобы relay не видел даже публичный ключ отправителя
- [ ] **Passphrase-lock локальной базы**: Argon2id + XChaCha20 вокруг IndexedDB
- [ ] **Мультиустройство**: device-linking по QR + отдельная сессия на устройство
- [ ] **Push-уведомления**: Web Push (VAPID) для PWA, FCM-опционально
- [ ] **Группы**: MLS (RFC 9420) или sender-key схема
- [ ] **Ответы/реакции/пересылка** в протоколе payload'ов

## Дальше (v0.3+)

- [ ] **Nostr-транспорт** (NIP-04/44 совместимость не нужна, но relay-сеть — да)
- [ ] **I2P-транспорт** и авто-выбор по доступности
- [ ] **Bluetooth / LoRa mesh** без интернета (мост через телефон)
- [ ] **Голос/видео** на WebRTC с тем же ratchet для сигналинга
- [ ] **Исчезающие файлы** с потоковой передачей
- [ ] **Детерминированный PoW-пул** и защита от Sybil на публичных relay
- [ ] **Аудит** криптографии сторонними специалистами
- [ ] **CLI-клиент** для скриптов и серверов
- [ ] **Экспорт переписки** в зашифрованный архив

## Идеи, которые надо обсудить

* Push-уведомления неизбежно раскрывают relay'ю устройство — можно сделать
  «уведомления через свой relay» с минимальным раскрытием.
* Мультиустройство и forward secrecy конфликтуют: нужно решить, как
  синхронизировать ratchet-состояние (обычно — отдельная сессия на устройство).
* Группы: MLS даёт корректную FS/PCS, но тяжелее в реализации, чем sender keys.

Хотите что-то из этого? Открывайте issue с описанием сценария — приоритеты
зависят от реальных задач, а не от красоты списка.
